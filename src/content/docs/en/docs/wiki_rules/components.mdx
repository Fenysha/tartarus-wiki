## Использование компонентов

Компоненты расширяют стандартный Markdown и позволяют использовать в документах элементы интерфейса, разработанные специально для вики.

Компоненты находятся в:

```text
src/components/
```

В MDX-документ они подключаются через alias:

```mdx
import ComponentName from '@components/ComponentName.astro';
```

После импорта компонент можно использовать непосредственно в содержимом страницы.

> **Важно:** Astro-компоненты доступны только в `.mdx`-документах. Обычный `.md` не поддерживает их использование таким способом.

## DocumentHeader

`DocumentHeader` — техническая шапка документа.

Используется для отображения классификации, уровня угрозы и текущего статуса документа.

### Импорт

```mdx
import DocumentHeader from '@components/DocumentHeader.astro';
```

### Использование

```mdx
<DocumentHeader
    security="EKHU"
    threat="LOW"
    status="OPEN"
/>
```

### Параметры

<DataTable
labelHeader="Параметр"
valueHeader="Тип"
rows={[
{ label: 'security', value: 'SecurityLevel' },
{ label: 'threat', value: 'ThreatLevel' },
{ label: 'status', value: 'DocumentStatus' },
]}
/>

### Security

Уровень секретности документа.

Доступные значения:

```text
EKHU
LIMN
SIGMA
THETA
OMEGA
TARTAR
```

Пример:

```mdx
<DocumentHeader
    security="OMEGA"
    threat="HIGH"
    status="CLASSIFIED"
/>
```

### Threat

Уровень потенциальной угрозы.

Доступные значения:

```text
LOW
MEDIUM
HIGH
CRITICAL
UNKNOWN
```

### Status

Текущее состояние документа.

Доступные значения:

```text
OPEN
RESTRICTED
SEALED
CORRUPTED
CLASSIFIED
```

### Рекомендации

`DocumentHeader` рекомендуется размещать сразу после frontmatter и импортов.

```mdx
---
title: Название документа
---

import DocumentHeader from '@components/DocumentHeader.astro';

<DocumentHeader
    security="EKHU"
    threat="LOW"
    status="OPEN"
/>

## Содержание
```

Не следует использовать высокую классификацию только ради визуального оформления.

## DataTable

`DataTable` предназначен для отображения структурированных данных в едином стиле вики.

Подходит для характеристик, параметров, классификаций, кратких сводок и других данных, которые удобно представить в формате «параметр → значение».

### Импорт

```mdx
import DataTable from '@components/DataTable.astro';
```

### Базовое использование

```mdx
<DataTable
    rows={[
        { label: 'Статус', value: 'Активен' },
        { label: 'Версия', value: '1.0' },
        { label: 'Тип', value: 'Архивный' },
    ]}
/>
```

### Параметры

<DataTable
labelHeader="Параметр"
valueHeader="Тип"
rows={[
{ label: 'rows', value: 'Массив объектов Row' },
{ label: 'labelHeader', value: 'Строка, необязательно' },
{ label: 'valueHeader', value: 'Строка, необязательно' },
]}
/>

### `rows`

Основное содержимое таблицы.

Каждая строка должна содержать:

```ts
{
    label: string;
    value: string;
}
```

Например:

```mdx
<DataTable
    rows={[
        { label: 'Размер', value: '32 × 32' },
        { label: 'Формат', value: 'PNG' },
        { label: 'Статус', value: 'Подтверждён' },
    ]}
/>
```

### Заголовки

По умолчанию используются:

```text
Параметр
Значение
```

Их можно изменить:

```mdx
<DataTable
    labelHeader="Код"
    valueHeader="Описание"
    rows={[
        { label: 'EKHU', value: 'Открытая информация' },
        { label: 'LIMN', value: 'Служебная информация' },
    ]}
/>
```

### Рекомендации

Используйте `DataTable`, когда информация имеет естественную табличную структуру.

Не следует использовать компонент для больших текстовых блоков.

Плохо:

```text
Параметр: длинный абзац текста...
Параметр: ещё один длинный абзац...
```

Лучше использовать обычный Markdown:

```md
## Описание

Большой объём текста следует оформлять обычными абзацами.
```

## ImagePanel

`ImagePanel` используется для отображения изображений в стиле архивной записи.

Компонент добавляет техническую информацию, подпись и идентификатор материала.

### Импорт

```mdx
import ImagePanel from '@components/ImagePanel.astro';
```

### Использование

```mdx
<ImagePanel
    src="/images/example.jpg"
    alt="Описание изображения"
    caption="Подпись архивного материала"
    reference="IMG-0001"
    source="ARCHIVE"
/>
```

### Параметры

<DataTable
labelHeader="Параметр"
valueHeader="Назначение"
rows={[
{ label: 'src', value: 'Путь к изображению' },
{ label: 'alt', value: 'Текстовое описание изображения' },
{ label: 'caption', value: 'Видимая подпись' },
{ label: 'reference', value: 'Идентификатор архивной записи' },
{ label: 'source', value: 'Источник материала' },
]}
/>

### `src`

Путь к изображению.

Например:

```mdx
src="/images/archive/example.jpg"
```

### `alt`

Описание изображения для пользователей, которые не могут его просмотреть, а также для accessibility.

Не следует оставлять `alt` пустым без причины.

```mdx
alt="Внешний вид объекта"
```

### `caption`

Подпись изображения:

```mdx
caption="Общий вид объекта."
```

Она должна кратко объяснять, что именно изображено.

### `reference`

Идентификатор материала:

```mdx
reference="IMG-0001"
```

Формат идентификатора не является техническим требованием Astro. Он используется как часть визуального и логического оформления архива.

### `source`

Источник изображения:

```mdx
source="ARCHIVE"
```

Можно использовать название архива, организации, коллекции или другой источник материала.

## Комбинирование компонентов

Компоненты можно использовать вместе в одном документе.

Например:

```mdx
---
title: Пример документа
---

import DocumentHeader from '@components/DocumentHeader.astro';
import DataTable from '@components/DataTable.astro';
import ImagePanel from '@components/ImagePanel.astro';

<DocumentHeader
    security="SIGMA"
    threat="MEDIUM"
    status="OPEN"
/>

## Краткая сводка

Краткое описание документа.

<ImagePanel
    src="/images/example.jpg"
    alt="Пример архивного изображения"
    caption="Архивный материал."
    reference="IMG-0001"
    source="ARCHIVE"
/>

## Основные сведения

<DataTable
    rows={[
        { label: 'Статус', value: 'Активен' },
        { label: 'Тип', value: 'Архивный' },
        { label: 'Версия', value: '1.0' },
    ]}
/>

## Дополнительная информация

Основной текст документа.
```

Рекомендуемый порядок:

```text
DocumentHeader
      ↓
Краткая сводка
      ↓
ImagePanel / DataTable
      ↓
Основной текст
      ↓
Дополнительные материалы
```

Это не является строгим техническим требованием. Порядок следует выбирать исходя из содержания документа.

## Импорт компонентов

Для компонентов вики используется alias:

```mdx
@components/
```

Например:

```mdx
import DataTable from '@components/DataTable.astro';
```

Не рекомендуется использовать длинные относительные пути:

```mdx
import DataTable from '../../../../components/DataTable.astro';
```

Alias сохраняет одинаковый импорт независимо от того, насколько глубоко расположен текущий документ.

## Создание нового компонента

Новые компоненты размещаются в:

```text
src/components/
```

Например:

```text
src/components/
├── DataTable.astro
├── DocumentHeader.astro
├── ImagePanel.astro
└── NewComponent.astro
```

Компонент должен иметь понятное название и самостоятельное назначение.

Не рекомендуется создавать компонент для элемента, который используется один раз и не требует отдельной логики или оформления.

Перед созданием нового компонента стоит проверить, нельзя ли решить задачу стандартным Markdown или уже существующим компонентом.

## Компоненты и стили

Компонент должен самостоятельно отвечать за своё визуальное оформление.

Например:

```text
DataTable.astro
    ├── HTML
    ├── логика
    └── CSS
```

Не следует переносить стили конкретного компонента в каждую отдельную страницу.

Это позволяет изменить внешний вид компонента централизованно.

## Типизация

Astro-компоненты должны описывать ожидаемые параметры через TypeScript.

Например:

```ts
interface Props {
    security?: SecurityLevel;
    threat?: ThreatLevel;
    status?: DocumentStatus;
}
```

Это позволяет редактору обнаруживать ошибки ещё до публикации документа.

Например, если компонент принимает:

```text
EKHU
LIMN
SIGMA
THETA
OMEGA
TARTAR
```

значение:

```mdx
security="SECRET"
```

должно считаться ошибочным.

## Общий принцип

Компоненты вики являются инструментом оформления и структурирования информации.

Они не должны заменять содержание документа.

Используйте:

```text
Markdown
    ↓
обычный текст, списки, заголовки, цитаты

DataTable
    ↓
структурированные данные

ImagePanel
    ↓
архивные изображения

DocumentHeader
    ↓
метаданные и классификация документа
```

Если информацию можно удобно выразить стандартным Markdown, предпочтительно использовать Markdown.

Компонент стоит создавать тогда, когда он предоставляет повторно используемую структуру, визуальное оформление или функциональность, отсутствующую в стандартном Markdown.
